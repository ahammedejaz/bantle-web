## Query 4 — CHECK constraints

[query]
```sql
SELECT
  rel.relname AS table_name,
  con.conname AS constraint_name,
  pg_get_constraintdef(con.oid) AS definition
FROM pg_constraint con
JOIN pg_class rel ON rel.oid = con.conrelid
JOIN pg_namespace nsp ON nsp.oid = rel.relnamespace
WHERE rel.relname IN ('profiles', 'listings', 'deals')
  AND nsp.nspname = 'public'
  AND con.contype = 'c'
ORDER BY rel.relname, con.conname;
```
[/query]

[result]
| table_name | constraint_name | definition |
|---|---|---|
| deals | deals_agreed_price_range | `CHECK (((agreed_price >= 1) AND (agreed_price <= 100000)))` |
| deals | deals_distinct_parties | `CHECK ((host_id IS DISTINCT FROM buyer_id))` |
| deals | deals_status_check | `CHECK ((status = ANY (ARRAY['pending'::text, 'active'::text, 'completed'::text, 'disputed'::text, 'cancelled'::text])))` |
| listings | listings_duration_months_range | `CHECK (((duration_months >= 1) AND (duration_months <= 24)))` |

## Query 5 — Foreign key constraints

[query]
```sql
SELECT
  conrelid::regclass AS table_name,
  conname AS fk_name,
  pg_get_constraintdef(con.oid) AS definition
FROM pg_constraint con
JOIN pg_class rel ON rel.oid = con.conrelid
JOIN pg_namespace nsp ON nsp.oid = rel.relnamespace
WHERE rel.relname IN ('listings', 'deals', 'user_reports', 'profiles')
  AND nsp.nspname = 'public'
  AND con.contype = 'f'
ORDER BY rel.relname, conname;
```
[/query]

[result]
| table_name | fk_name | definition |
|---|---|---|
| deals | deals_buyer_id_fkey | `FOREIGN KEY (buyer_id) REFERENCES profiles(id) ON DELETE SET NULL` |
| deals | deals_conversation_id_fkey | `FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE SET NULL` |
| deals | deals_host_id_fkey | `FOREIGN KEY (host_id) REFERENCES profiles(id) ON DELETE SET NULL` |

Notes for Phase 3:

- Joining listings/deals back to a banned user is safe — `listings.user_id` and `deals.host_id`/`buyer_id` are valid FKs into `profiles`.
- Hard-deleting a profile cascades through `auth.users → profiles` (CASCADE) and `profiles → listings` (CASCADE), but `deals` rows survive with `host_id`/`buyer_id` nulled. Phase 3 Users management should not surface deals with null counterparties as "active" without an explicit filter.
- `user_reports.reporter_id` is the only ON DELETE CASCADE among report FKs — deleting a profile keeps reports filed against them (reported_id is SET NULL) but wipes the ones they filed.
[/result]

## Query 6 — Ban state breakdown

[query]
```sql
SELECT
  COUNT(*) AS total_users,
  COUNT(*) FILTER (WHERE deleted_at IS NOT NULL) AS soft_deleted,
  COUNT(*) FILTER (WHERE banned_until > now()) AS temp_banned,
  COUNT(*) FILTER (WHERE permanently_banned = true) AS perm_banned,
  COUNT(*) FILTER (WHERE push_token IS NOT NULL) AS has_push_token,
  COUNT(*) FILTER (WHERE is_admin = true) AS admins
FROM profiles;
```
[/query]
